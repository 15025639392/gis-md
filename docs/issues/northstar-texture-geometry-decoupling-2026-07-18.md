# 北极星：纹理/几何解耦（Universal Texture）—— 可验证目标 + 执行框架

> 成文 2026-07-18。给**新会话**带着可验证靶子开跑用。这不是实现指南，是**目标函数 + 验收闸门 + 执行阶段**。实现方案由新会话在 Phase 1 调研后出设计再拍板。

---

## 0. 一句话

把**影像 LOD 从地形几何 LOD 解耦**：地形几何只细化到 DEM 真实分辨率就停，影像走一套**有界的、与几何无关的**纹理通路继续到高清。**这本质是一次性能重构（砍瓦片爆炸），GE 观感是副产品。**

---

## 1. 为什么造这个引擎 / 为什么这是北极星

- **造引擎的理由**：没有现成原生地球引擎在**性能 / 功能 / 跨平台**三头同时满足业务 + 扩张需求（cesium 跑得重、GE 闭源、其余功能或平台不够）。我们要的是对 **CPU/内存/GPU 调度的完全掌控权**，在最弱设备上、随业务扩张仍守住预算。**这是引擎的存在理由，也是所有架构取舍的第一坐标轴。**
- **为什么北极星是解耦**：上一会话代码插桩坐实——斜视底边 artifact（洞）的根不是遮挡，是**影像清晰度反向逼地形几何假细分**。这条耦合是本项目**资源爆炸的总闸**（见 §3）。解耦是手上杠杆最大的一次资源下降。

---

## 2. 优化目标函数（写死的哲学）

> **在"产品体验"这条地板之上，最小化"有界的"资源占用。**

- **体验 = 硬约束（地板，不能降）**：近景影像清晰度、零洞、无 LOD pop、地形匹配 DEM 分辨率。
- **资源 = 被最小化的量**：CPU（selector / clip / 主线程）、内存（VBO / 纹理 / 缓存）、GPU（draw call / 上传 / 带宽）。**不降体验的前提下，越低越好。**
- **"有界"是三个词里最关键的**（有界 + 低 + 跨设备可预测）：资源**不随缩放/瓦片数无限膨胀**。跨平台的本质就是"最弱设备上放大也不爆"。峰值有上限比均值低更重要。

---

## 3. 问题本质（根因已定死，别重新调查）

**耦合链**：影像 `RasterMappedToTilesetTile::isMoreDetailAvailable()` → 地形瓦片 `isRenderable()` 判 false（`TileSelectionRasterOverlayPreparer.h:46`）→ selector 继续细化 → 把 z12 DEM **上采样**到 z13-17 只为托更清的高德影像（DEM 一点没变细，纯假细分）。

**假细分烧的是瓦片数量**，而瓦片数是这一会话所有性能痛点的**公因子**：
- selector 12-24ms —— 随 visited 瓦片数线性涨
- 上采样 clip 主线程尖刺 —— 每假瓦片一次 clip
- 上传 / 内存 / draw call —— 每片都要
- prefetchFill 359ms、notReady 积压、透天空的洞 —— 都是瓦片多的次生

**⟹ 解耦一刀砍掉瓦片爆炸，同时压 selector / clip / 上传 / 内存 / draw。这是它值得做的真正理由。**

**几何该细到哪停**：细到**网格间距 ≈ DEM 源分辨率**就停，再细是假的。FABDEM 源 = 30m；当前 grid65 只生成到 z12（native），z12 网格间距 ≈133m（重庆纬度，8.5km/64），其实**还没到 30m 源的极限**——理论上 native 数据可重生成到 ~z14 才吃满 FABDEM。所以"几何 cap"= **native 地形数据的真实上限（当前 z12；可选重生成到 ~z14 吃满 30m）**，z(native+1) 及以上全是"为影像假细分"，要消除。影像继续到 z18 由解耦纹理通路供给。**精确 cap 级别 Phase 1 用真实数据算，别拍脑袋。**

**排除项（别再查）**：occlusion 不是洞的原因（settled `occluded=0`，OCCDIAG 坐实）；洞是加载暂态非几何 bug。

## 4. 目标架构：有界共享纹理缓存（不是逐瓦片合成）

用 §2 的"有界"尺子筛方案：

| 档 | 做法 | 有界性 | 裁决 |
|---|---|---|---|
| A 只拆细化驱动 | 地形按 DEM 误差细化，影像独立细化 | —— | **不完整**：没解"粗几何怎么显高清影像" |
| B 逐瓦片合成 | 每片离屏合成覆盖它的更深影像成一张纹理 | ❌ **内存随瓦片数涨**（每片 2K≈16MB×40 片=640MB 崩） | 违反核心价值，只可作过渡 |
| **C 共享 atlas 虚拟纹理** | 一张视野中心的大 atlas + 间接纹理 + feedback，几何采样虚拟纹理，按可见性流式换页 | ✅ **内存被屏幕分辨率封死，与缩放/瓦片数无关** | **目标形态** |

**目标 = C 的形状（有界共享纹理缓存）。** GE 的 Universal Texture 就是这个。

**路径可以逐瓦片起步，但数据模型必须能长成 C**：纹理源抽象成"页（page）"，撞内存墙时无缝换共享 atlas，不返工。**别做一个长不成 C 的 B。**

**诚实的账（Phase 1 必须真机量）**：C 不免费——feedback buffer 回读可能 stall、逐 fragment 间接采样有开销。"有界不等于免费"。要么直接奔 C 但先量固定开销，要么做能长成 C 的过渡形态。

## 5. 可验证闸门表（北极星达成 = 全过）

| 维度 | 判据 | 现状（耦合） |
|---|---|---|
| **不降体验（地板）** | 固定相机参考集（低空 nadir / 斜视 / 深近景）：影像清晰度 ≥ 现状、零洞、无 pop、地形匹配 DEM | Phase 0 先拍基线 |
| **有界 ⭐核心一击** | 从 z12 放大到 z18 等效、固定屏幕下 {瓦片数、地形 VBO 字节、影像纹理字节、selector ms、draw call、峰值内存} **斜率≈0（不涨）** | 全随缩放**爆炸** |
| **低** | 同视角下每项绝对值 **< 耦合基线** | 基线 |
| **可预测** | p99 帧时 / 峰值内存**有上限**（盯尖峰不盯均值） | 尖峰失控 |

**验收核心一击**：**放大近景，瓦片数/内存/selector 保持平，而影像照样清。** 这一个测试过了整套就成了；没过就是没做对。

## 6. 测量台硬要求（把栽过的坑写进去）

**"越低越好"只有能可靠测量时才成立，而测量是本项目最弱的一环。** 必守：
- **release 构建**（-O2）测性能，**绝不用 debug**（-O0 膨胀 ~3×，假象，见 [[perf-measured-on-debug-build]]）。
- **编译期钉死相机**（`SceneCameraConfig.obliqueElevationDegrees` 等），**不用 swipe**（惯性失控 + 跨重启不可复现，见 [[ge-loading-experience-gap-2026-07-17]] 教训）。
- **位姿无关 logcat 指标**（瓦片数 / VBO / 纹理字节 / selector ms / draw call / 峰值内存），**不靠截图字节量当代理**（被相机惯性终点污染）。
- **现在就采耦合态基线**（"之前"的硬数字 + 参考画质截图），否则北极星做完你我都不知道赢没赢。
- 分析拖动帧**排除 frame≤3 启动帧**（request 分发一次性膨胀会被误当拖动）。
- `pendUp` 是判上传瓶颈的关键字段；`interaction`/`reqMotion` 判运动态。

## 7. 执行阶段

- **Phase 0 — 立基线 + 测量台（先做，别跳）**：release + 钉相机 + 位姿无关指标，采耦合态"之前"硬数字 + 参考画质截图。产出 §5 闸门表的"现状"列真实值。
- **Phase 1 — 调研 + 出设计**：扒 `.ref/osgearth`（影像层 vs 地形 LOD 关系、有没有虚拟纹理）为基准，另看 cesium-native/maplibre；出 design doc 落 `docs/issues/`，**含 C 的移动端固定开销真机 PoC 数据 + 内存账 + GLES sampler 上限核算**；拆"几何 cap 精确级别"（真实数据算）；**让用户拍板档位/路径**，再写大码。
- **Phase 2+ — 实现**：按闸门表每步验收；先拆 `isMoreDetailAvailable→refine` 耦合（几何按 DEM 误差 cap），再上解耦纹理通路。

- overlay 系统规模：`RasterMappedToTilesetTile.cpp` 625 行 + `RasterOverlayTileProvider.cpp` 4660 行；**逐地形瓦片贴、逐真实顶点算 UV、影像 LOD 绑地形 LOD**。这是要重建的主战场，冲击面最大。

## 9. 待新会话调研收敛的开放决策

1. **档位/路径**：直接奔 C（共享 atlas VT）vs 做"能长成 C 的过渡形态"——取决于 C 的移动端固定开销真机 PoC（Phase 1 量）。
2. **几何 cap 精确级别**：native 保持 z12 vs 重生成数据到 ~z14 吃满 30m FABDEM。
3. **影像纹理通路**：合成 atlas 分辨率、页大小、压缩格式（ETC2/ASTC）、feedback 机制（真 GPU feedback vs CPU 预测可见页）。
4. **过渡期兼容**：解耦改造期地形/影像半坏——一次性替换 vs flag 并存（参照上次一次性替换的经验）。
