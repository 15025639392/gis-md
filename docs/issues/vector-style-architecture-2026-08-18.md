# 矢量样式架构设计 — 上半借形、下半原创(2026-08-18)

> **状态**:架构定调已获用户同意(2026-08-18 会话)。样式来源(自建子集 vs
> style.json v8 兼容)是上半部的**可换叶子,未拍板**,见 §6。
> 判据锚点 = `docs/northstar/vector.md` **V26**(D2 节);本文回答"怎么搭",
> 判据状态不在此重复。

## 0. 一句话

**统一"样式从哪来、怎么求值"(上半部,借 maplibre 收敛形态),
分治"编译成各路运行时参数"(下半部,原创:表示能力契约 + 成本类失效路由)。**
上半部三家引擎独立收敛、无发明空间;下半部 maplibre 根本没有我们的难题
(四条异构表示路),无处可抄、必须原创。

## 1. 调研基准(`.ref` 数据,冻结于本文)

权威源:`.ref/maplibre-gl-style-spec`(v25.0.1,浅克隆,对齐
`.ref/maplibre-gl-js` package.json 的依赖 major)。maplibre-gl-js 本体不含
spec 定义(外部 npm 包,100 个源文件只 import),故单独拉取。

### 1.1 规模(TS 行数,非 test)

| 模块 | 行数 | 说明 |
|---|---|---|
| expression 引擎 | **7765** | 87 个算子,解释型,动态类型 |
| validate | 2103 | v8 schema 校验器 |
| function(老式 stop) | 602 | 遗留插值函数 |
| feature_filter | 573 | 14 个谓词 |

### 1.2 本引擎已覆盖 vs 全 spec

| 维度 | maplibre v25 | 本引擎 | 差距性质 |
|---|---|---|---|
| filter 谓词 | 14 个 + 表达式 filter | `StyleFilter` 基本齐平,缺 `within`(地理谓词) | **齐平** |
| expression 算子 | 87 | `StyleExpression` 5 个(literal/get/zoom/match/interpolateLinear) | 差 82,但大部分**消费不了**(见 1.3) |
| layer 类型 | 10 | 面/线/点三分工(≈fill/line/symbol 子集) | 表示架构决定,非样式层能补 |
| JSON 解析 | 完整 v8 + validate | **无**(纯 C++ builder API) | "外置"缺的那块 |

### 1.3 落地率(吃全 spec 的性价比塌方点)

- symbol layer **59 属性**(layout 45),本引擎符号链实现 **~6 个**;
- line layer **18 属性**,本引擎线场消费 **2 个**(全局色 + 宽度 ramp)——
  逐要素色都没有,即 D2 编码无分类通道那条债(V26 差距、V9 半个语义)。
- 结论:即便解析全 spec,三分工渲染只能落地一小撮,其余解析成果是死代码。

## 2. 为什么 maplibre 必要不充分(约束还原)

| 它的约束 | 导致的设计 | 我们有吗 |
|---|---|---|
| 所有 layer 走同一条 GPU 管线(source→tile→bucket→draw) | 一套 schema 描述所有 layer | ❌ 四条异构路(drape/场/符号/交互) |
| 面向设计师(Studio GUI) | 87 算子解释型表达式语言 | ❌ 样式作者是自己 |
| 样式即商品(第三方生态) | 严格版本化 spec + 2103 行 validator | ❌ 落地率低(§1.3) |
| web 热加载 | JSON 文档 + diff | ✅ **同要**(V26) |

**它真正的宝石不是 JSON 格式,是属性失效成本分类**:每个属性标注
layout(改了要重镶嵌)/ paint(uniform 或顶点属性)/ data-driven 与否。
样式 diff 因此自动映射到最小重建量——热加载"高效"的真正来源,格式只是皮。

### 2.1 对照系(为什么上半部是"收敛结果")

| 引擎 | 样式形态 | 文档级换肤 |
|---|---|---|
| maplibre / osgEarth | 声明式文档 + filter + 建桶期逐要素求值 | ✅ 两家独立收敛同构 |
| Cesium | 命令式 per-entity 属性对象 | ❌ **即本引擎今天的形态**(builder API 硬编码 GLESView) |
| deck.gl | accessor 函数即样式 | ❌ 不可序列化 → 无外置 |

诚实标注:本引擎 `StyleExpression` 头注释明写"MapLibre style-spec 子集",
不算完全独立收敛;但**语义分割**(颜色烘顶点禁 zoom / 宽度走 uniform 禁
properties)是被自己的重镶成本逼出来的,与 maplibre 的 paint/layout 分类
殊途同归——同一约束下两次得出同一解,比"maplibre 这么做所以对"强得多。

## 3. 架构:五层

```
        ┌─────────────────────────────────────────────┐
  上层  │ StyleDocument(统一源模型)                     │
  借形  │   sources[] + layers[]{type,filter,           │
        │     paint,layout,minzoom,maxzoom}             │
        └──────────────────┬──────────────────────────┘
              ▲ parse       │  ← §6 A/B 叶子:parser 认什么 schema,可换可延后
              │ (JSON→Doc)  │
        ┌─────┴─────────────▼──────────────────────────┐
  内核  │ 求值内核:StyleExpression + StyleFilter         │
  已有  │   (属性上下文求值,已共享、已做对,不动)          │
        └──────────────────┬──────────────────────────┘
                           │ StyleCompiler(加载期编译一次)
  原创  │  ①能力契约校验(fail-loud) ②成本类失效路由      │
  下半  └────────────┬────────────┬──────────────┬─────┘
              ▼            ▼            ▼              ▼
        VectorRaster    场uniform    FeatureRender   OverlayStyle
        Style(面)       +约束(线)     Style(点)       +state(交互)
                           │
        ┌──────────────────▼──────────────────────────┐
  gate  │ revision 失效传播:Doc 变→diff→按成本类最小重建 │  ← V26 差距#2 的解法
        └───────────────────────────────────────────────┘
```

**为什么不追求"一套样式模型"**:四条路的物理表示与运行时语义根本不同
(面=重栅格化、线=D2 编码物理约束、点=图集+重镶、交互=feature-state 每帧
切 uniform)。maplibre 一套 schema 成立的前提是渲染均质;本引擎不均质,
强行塞一个 struct 是把不该耦合的耦合。统一在源模型与求值内核两层,
分治在编译目标层。

## 4. 下半部原创件:接口草案

### 4.1 表示能力契约(maplibre 没有、我们必须有)

每条消费路声明:`{可消费属性集,每属性 → 成本类}`。
`StyleCompiler` 在**加载期**拿 StyleDocument 对契约校验:

- 路能消费 → 编译进该路的运行时参数;
- 路不能消费 → **显式报出**(诊断行/加载错误),不许静默吞。
  例:`line-dasharray` 撞 D2 编码物理边界(拿不到沿线弧长,V9 半个语义)
  ——必须加载期告知,而不是渲染出来不对。

契约的另一面是**防 schema 过度承诺**:合法样式文档不该能要求表示画不出的
东西而无人知晓。maplibre 永远不需要这个(表示均质);这层就是本架构
真正"新"的部分。

### 4.2 成本类(初版三档,`推断`——实现期可能重划,见 §7)

| 成本类 | 语义 | 典型属性 | 触发的重建 |
|---|---|---|---|
| **Uniform** | 帧级免费 | 线色/透明度/宽度 ramp/符号遮挡参数 | 改 uniform,零重建 |
| **Re-bake** | 页/场重烘 | 线 filter/分级规则、面 fill 色、drape 层序 | drape 页重栅格化 / 场页重 scatter |
| **Re-tess** | 重镶嵌 | 符号表达式/图形/标注字段 | 瓦片桶重镶(worker) |

失效时序:`Doc.set(newDoc)` → diff 属性集 → 逐属性查成本类 → 聚合成
各路最小失效指令(如"场:只换 uniform;drape:全页失效;符号:不动")。

- **便宜**:不新增机器,只是把四条路已经在做的事(drape 重栅格化、场重
  scatter、符号重镶、overlay uniform 切换)形式化成接口。
- **高效**:效率唯一杠杆在失效粒度——换线色不该重烘场页。没有任何架构
  能让重栅格化本身免费,能省的只有"别做不必要的那次"。

### 4.3 失效粒度与编译时机(默认决策,按推荐项推进、可推翻)

- **失效粒度:先整份 Doc diff、整路重建**。换肤是低频操作,逐 layer 脏
  标记的复杂度等有性能证据再上。
- **编译时机:加载期一次**,非每帧。换肤触发一次重编译+按成本类重建,
  稳态零成本。

## 5. 分期(gate 优先;工时 AI 协作基准,量级仅供排序)

| 期 | 内容 | 为什么是这个顺序 | 量级 |
|---|---|---|---|
| **一期** | 面/线两路的**样式失效通路**:drape 补 setStyle + 页失效联动;场突破"首帧 Config 快照"(运行期重注入 + 场页失效) | **gate**:V26 差距#2。无论样式格式选什么,不补这条只能重启进程换肤。格式决策可以晚,通路不能晚 | 1-2 天 |
| **二期** | StyleDocument + parser(§6 A/B 在此拍板)+ StyleCompiler(契约校验+成本类路由) | 依赖一期的失效入口才有东西可路由 | 2-3 天 |
| **三期** | 交互路(VectorLayer/OverlayStyle)纳入源模型,编译到 feature-state 运行时样式 | 它已有 setStyle 能运行期改,不在 gate 痛点上;且牵动拾取/选择子系统,单独收口 | 1-2 天 |

## 6. 上半部叶子:样式来源 A/B(未拍板,降级为 parser 决策)

| | A. 自建精简子集 | B. maplibre style.json v8 兼容 |
|---|---|---|
| 成本 | 数百行(JSON 解析层;算子/filter 已在跑) | 数千行(算子子集移植+schema+版本税) |
| 红利 | 只能换"自己的"样式 | 白吃 OpenMapTiles 等现成样式(40-140 layer) |
| 落地率 | 100% | 低(§1.3) |

架构定调后 A/B 只影响 parser 层,**换 schema 不动下面四层**——这正是
"先敲定架构"的意义:A/B 是叶子不是根。北极星 F 节挂待拍板项;判据是
"要表达力还是要生态兼容",归用户。

## 7. 已判死 / 边界 / 失效条件

- **不自造样式语言**(判死):parser/validator/文档/工具链全是商品件成本,
  差异化收益 ≈ 0,还背语言维护债。上半部的"新"= 纯负收益。
- **不预拍 A/B**;若日后真要吃第三方生态,上半部换严格 v8,§6 B 列成本
  全部生效——这是本设计的显式失效边界之一。
- **成本类三档是推断**:若实现期发现场/drape 重建粒度比页更粗(如只能整源
  重建),成本类要重划。
- **本文冻结后不改**(docs/issues 协议);后续推进以 northstar V26 为准。
