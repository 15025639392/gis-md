# 地球引擎数据承载目录

地球引擎承载的不只是“地图瓦片”。它是一个把地球空间、时间、三维场景和业务对象统一组织起来的运行时。AI 设计数据接入或图层能力前，必须先判断数据属于哪一类，以及它的坐标、单位、时间、LOD、样式、权限和缓存规则。

## 数据总类

地球引擎通常承载以下数据：

- 底图影像与地图瓦片
- 地形、高程、深度与地表模型
- 矢量要素与业务图层
- 3D Tiles 与三维城市/倾斜摄影/BIM
- 点云
- glTF/glb 模型与符号模型
- 遥感栅格与科学栅格
- 时序数据与动态对象
- 实时传感器与流数据
- 标注、测量、绘制和用户编辑数据
- 空间分析结果
- 行政区划、地名、POI、路网与地理编码数据
- 样式、材质、符号和渲染规则
- 元数据、权限、版权、数据血缘
- 离线包、缓存、索引和瓦片清单

## 1. 底图影像与地图瓦片

典型数据：

- 卫星影像
- 航空影像
- 电子地图底图
- XYZ/TMS/WMTS 瓦片
- WMS 动态地图图层

必须明确：

- tile scheme：XYZ、TMS、WMTS TileMatrixSet 或自定义。
- CRS：常见为 `EPSG:3857` 或地理瓦片。
- 图层顺序、透明度、色彩空间、attribution。
- 最大/最小 zoom，覆盖范围和无数据区域。
- 失败瓦片的占位、重试和降级策略。

## 2. 地形、高程、深度与地表模型

典型数据：

- DEM、DSM、DTM
- terrain tile
- heightmap
- quantized mesh
- bathymetry 水深
- slope/aspect 派生产品

必须明确：

- 高度基准：ellipsoid height、orthometric height、EGM96/EGM2008 或数据源自定义。
- 单位：通常为 meter。
- 采样间距、分辨率、无效值。
- 地形 LOD、skirt、接缝和法线。
- 高程查询与渲染地形是否使用同一数据源。

## 3. 矢量要素与业务图层

典型数据：

- GeoJSON、TopoJSON、WKT/WKB
- MVT 矢量瓦片
- 行政区划、地块、管线、道路、水系
- 点、线、面、多几何
- 业务对象，例如设备、项目、风险区、巡检区域

必须明确：

- 坐标顺序和 CRS。
- 几何合法性和拓扑要求。
- 属性 schema 和 feature id。
- 样式规则、交互规则、编辑规则。
- 大数据量时是否需要瓦片化、简化、聚合或空间索引。

## 4. 3D Tiles 与三维场景

典型数据：

- 倾斜摄影
- 三维城市
- BIM/CAD 转换结果
- 点云 tileset
- 实景三维 mesh
- implicit tiling tileset

必须明确：

- tileset 版本、extensions、geometricError、refine 策略。
- bounding volume 类型和坐标解释。
- content 类型：b3dm、i3dm、pnts、cmpt、glTF、subtree。
- feature metadata、picking、styling。
- GPU 资源释放和 tileset traversal 策略。

## 5. 点云

典型数据：

- LAS/LAZ
- 3D Tiles pnts
- LiDAR 点云
- 摄影测量点云
- 实时扫描点云

必须明确：

- 坐标系、单位和高度基准。
- 点属性：intensity、classification、return number、color、normal、timestamp。
- 点数量、LOD、空间索引、抽稀策略。
- 渲染方式：point size、attenuation、分类着色、高程着色。
- 拾取和剖面分析是否需要原始点属性。

## 6. 模型与符号

典型数据：

- glTF/glb
- 设备模型
- 车辆、飞机、船舶模型
- 标志牌、风机、塔杆、建筑单体
- 图标 billboard、label、marker

必须明确：

- 模型坐标原点、朝向、单位和缩放。
- 是否贴地、贴模型、绝对高度或相对高度。
- 动画、骨骼、材质、纹理。
- 批量实例化策略。
- picking 返回模型 id 还是业务对象 id。

## 7. 遥感栅格与科学栅格

典型数据：

- 多光谱、热红外、SAR
- NDVI、NDWI、NDBI
- 土地覆盖、温度、降水、风场、海浪
- GeoTIFF、COG、NetCDF、GRIB、Zarr

必须明确：

- 波段、时间、分辨率、nodata。
- 统计范围、拉伸、色带、单位。
- 重投影、重采样和金字塔策略。
- 大文件是否使用 COG、chunk、tile 或服务端裁剪。
- 科学数据的单位和有效范围不能被渲染样式覆盖。

## 8. 时序数据与动态对象

典型数据：

- 历史轨迹
- 动态车辆、船舶、飞机
- 时序影像
- 时序气象/海洋数据
- 施工进度、灾害演化、态势播放

必须明确：

- 时间字段、时区、时间精度。
- 插值方式：step、linear、spline、物理模型。
- 播放速度、时间窗口、缓存窗口。
- 过期数据和未来数据如何显示。
- 动态对象的位置、姿态、速度和轨迹是否分离。

## 9. 实时传感器与流数据

典型数据：

- AIS、ADS-B、GPS、IoT
- 气象站、水位站、视频点位
- 遥测、告警、事件流
- WebSocket、MQTT、SSE、轮询接口

必须明确：

- 数据频率、延迟、乱序和去重策略。
- 坐标质量和定位误差。
- 在线/离线状态。
- 告警等级和样式映射。
- 流数据与历史数据的合并边界。

## 10. 标注、测量、绘制和用户编辑数据

典型数据：

- 用户点线面标注
- 距离、面积、高程剖面
- 书签、视角、截图
- 编辑中的草图
- 协同编辑结果

必须明确：

- 编辑坐标是否贴地形。
- 测量使用 planar、spherical 还是 geodesic。
- 草图和已保存数据的 schema 是否不同。
- undo/redo 和冲突合并策略。
- 输出格式和精度。

## 11. 空间分析结果

典型数据：

- 缓冲区、叠加分析、裁剪结果
- 可视域、通视、日照阴影
- 等值线、热力图、聚合网格
- 路径规划、服务区、可达性
- 洪水淹没、坡度坡向、剖面分析

必须明确：

- 分析模型和参数。
- 输入数据版本。
- 输出 CRS、单位和误差。
- 是否为临时结果、可缓存结果或可持久化结果。
- 结果是否能反向追踪到输入数据。

## 12. 行政区划、地名、POI、路网与地理编码数据

典型数据：

- 行政边界
- 地名地址库
- POI
- 路网、拓扑、转向限制
- geocoding / reverse geocoding 索引

必须明确：

- 数据来源、更新时间、授权。
- 编码体系和层级关系。
- 坐标精度和匹配置信度。
- 路网拓扑和方向性。
- 搜索索引与空间索引的更新策略。

## 13. 样式、材质、符号和渲染规则

典型数据：

- 图层样式 JSON
- 色带、分类、阈值
- 3D 材质、纹理、PBR 参数
- label 规则、避让规则
- 业务状态到样式的映射

必须明确：

- 样式是否依赖 feature 属性或 metadata。
- 样式变化是否需要重建 GPU 资源。
- 默认样式和异常样式。
- 单位、色带范围和数据有效值。
- 样式版本与图层版本是否绑定。

点、线、面、标注和业务叠加层的详细样式规则见 `overlay-styling.md`。

## 14. 元数据、权限、版权和数据血缘

典型数据：

- attribution
- license
- 数据源版本
- 采集时间、生产时间、更新时间
- 精度、分辨率、质量等级
- 用户权限、可见范围、脱敏规则
- lineage / provenance

必须明确：

- attribution 是否必须显示。
- 数据能否缓存、离线、导出、截图。
- 用户权限是否影响图层、要素、属性或操作。
- 数据版本是否影响分析结果。
- AI 不得删除版权显示或绕过权限判断。

## 15. 离线包、缓存、索引和瓦片清单

典型数据：

- MBTiles、PMTiles、GeoPackage
- 离线 terrain package
- 离线 3D Tiles
- 本地空间索引
- manifest、checksum、版本清单

必须明确：

- 包格式和版本。
- 覆盖范围、层级、数据类型。
- 校验、增量更新、回滚。
- 存储配额和淘汰策略。
- 离线与在线数据冲突时的优先级。

## 数据接入必填清单

新增任何数据类型时，至少填写：

- 数据名称和分类。
- 数据格式和来源。
- CRS、坐标顺序、高度基准、单位。
- 时间维度和时区，如果存在。
- LOD、瓦片、索引或分页策略。
- 样式和交互方式。
- attribution、license、权限和脱敏规则。
- 缓存、离线和更新策略。
- 错误、缺失、nodata 和低质量数据处理。
- 测试和验收方式。

## 当前是否补齐

本文件给出的是地球引擎“应能承载的数据类型目录”。具体项目是否已经支持某类数据，必须由代码、Provider 实现、测试和产品需求共同证明。AI 不得因为本目录列出了某类数据，就声称引擎已经实现了该能力。
