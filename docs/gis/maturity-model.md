# 成熟度模型

本文件用于防止 AI 把“能跑”说成“成熟”。每个功能都必须标注成熟度。

## 等级

### Demo

特征：

- 能在单一示例中运行。
- 依赖固定数据。
- 错误处理很少。

不得宣称：

- 稳定。
- 可生产。
- 兼容多数据源。

### MVP

特征：

- 核心链路闭合。
- 有基本测试。
- 有 debug overlay。
- 支持最小真实 provider。

仍可能缺：

- 大规模性能。
- 完整错误恢复。
- 多端兼容。

### Alpha

特征：

- API 初步稳定。
- 支持多个 provider。
- 有单元和集成测试。
- 有基本性能指标。

风险：

- 可能有破坏性 API 变更。
- 边界场景仍不完整。

### Beta

特征：

- 主要 API 稳定。
- 常见 provider 通过兼容测试。
- 有视觉回归和压力测试。
- 错误恢复路径较完整。

### Production

特征：

- 长时间运行稳定。
- 有版本兼容策略。
- 有完整错误恢复。
- 有性能预算和压测报告。
- 有真实业务场景验证。
- 有文档、示例和迁移说明。

## 功能成熟度记录

每个能力建议记录：

```text
Feature:
  name:
  maturity:
  supported data:
  tests:
  known limitations:
  next required evidence:
```

## 宣称规则

- 没有测试，不得高于 Demo。
- 没有真实 provider，不得高于 MVP。
- 没有错误恢复和压力测试，不得高于 Alpha。
- 没有长期运行和版本策略，不得称 Production。

AI 最终回答中必须区分“已实现”、“设计支持”、“计划支持”。
