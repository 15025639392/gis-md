# 地球引擎测试与验收

地球引擎不能只靠“肉眼看起来正常”。AI 实现功能时必须给出可复现验证，至少覆盖单元测试、集成测试、视觉验证或性能观测中的相关部分。

## 单元测试

必须优先覆盖纯函数：

- degree/radian 转换。
- cartographic/ECEF/ENU 转换。
- tile key 与 bounds 互转。
- bounding volume 与 frustum 相交。
- screen-space error 计算。
- 请求优先级排序。
- cache eviction 策略。

单元测试应使用明确数值和容差，不要只断言“不是 null”。

## 集成测试

集成测试应覆盖：

- Provider 请求、取消、失败、重试。
- 影像瓦片加载到可渲染纹理。
- 地形瓦片加载到 mesh。
- 3D Tiles tileset traversal 和 content 加载。
- 相机移动触发 tile selection 更新。
- 图层添加、移除、销毁。
- picking、选择、绘制、编辑、测量和撤销/重做。

## 视觉验收

视觉测试至少关注：

- 首屏非空白。
- 地球完整显示，不被裁掉。
- 缩放到近地后不明显抖动。
- 影像和地形对齐。
- 白天/夜晚/日出日落环境状态合理。
- 天气、大气、云层等环境效果可关闭且不污染业务数据。
- 瓦片边界无明显裂缝。
- 文字、标注、控件不遮挡关键画面。
- debug overlay 不影响正常交互。
- 移动端手势、键盘取消和图层控制可用。

如果使用 Playwright，应保存桌面和移动视口截图。

## 性能验收

建议记录：

- FPS 或 frame time。
- draw call 数。
- 可见 tile 数。
- 请求队列长度。
- 正在加载 tile 数。
- GPU texture/buffer 数量。
- 主线程长任务。
- 内存和显存估算。

性能目标应按阶段设定。早期原型可以宽松，但必须保留观测点。

## 回归场景

每次大改后至少检查：

- 快速旋转地球。
- 连续缩放到近地再拉远。
- 横跨反经线移动。
- 高纬度地区观察。
- 网络慢或瓦片失败。
- 切换图层。
- 销毁并重建场景。

## 验收输出

AI 完成实现后，应在最终说明中给出：

- 修改了哪些模块。
- 坐标/CRS/单位假设。
- 使用了哪些测试或截图验证。
- 没有验证的风险。
- 下一步最值得补的测试。
