# 星空、大气、光照与天气系统

地球引擎不仅承载地表数据，也承载环境系统：星空、大气、太阳/月亮、光照、阴影、云、雾、雨、雪、海洋和时间。AI 实现这些能力时，必须明确它是物理正确、数据驱动近似，还是纯视觉效果。

## 三种真实性等级

任何环境效果都必须标明真实性等级：

- `visual-only`：只为视觉氛围服务，不参与分析。
- `approximate`：近似表达真实现象，可用于一般展示，但不能作为严肃分析依据。
- `analytic`：有明确数据来源、模型、单位和误差，可用于分析或业务判断。

例如：漂亮的云纹理通常是 `visual-only`；基于气象瓦片的云量可以是 `approximate`；基于正式气象数据同化结果的降水分析才可能接近 `analytic`。

## 时间系统

环境系统必须有统一时间源：

- `simulationTime`：场景模拟时间。
- `systemTime`：设备当前时间。
- `dataTime`：数据源发布时间或有效时间。
- `timezone`：显示时区。
- `timeRange`：时序播放范围。

太阳、月亮、星空、天气、动态对象和时序图层都应使用同一个时间控制器，不能各自读取系统时间。

## 星空

星空可由以下方式实现：

- 静态 skybox / cubemap。
- 程序化星空。
- 星表驱动渲染。
- 银河纹理和深空背景。

必须明确：

- 星空是否随时间、经纬度和相机姿态变化。
- 星表坐标系和历元，如果使用真实星表。
- 亮度、曝光、色温和大气影响。
- 是否只在夜侧或高空显示。
- 资源大小和移动端性能。

不要把静态星空伪装成天文精确。

## 太阳与月亮

太阳/月亮系统必须明确：

- 使用近似方向、天文算法，还是外部 ephemeris 数据。
- 输入时间是否为 UTC。
- 输出方向所在坐标系：ECEF、ECI、ENU 或 world space。
- 是否影响光照、阴影、大气散射、昼夜线和水面高光。
- 月相是否真实计算或只是纹理动画。

如果只用于视觉，必须标注 `visual-only` 或 `approximate`。

## 大气

大气效果包括：

- 地平线光晕。
- Rayleigh / Mie scattering 近似。
- 高空薄雾。
- 昼夜过渡。
- 空气透视。

必须明确：

- 大气参数是否可配置。
- 效果是否随太阳方向和相机高度变化。
- 是否与地球半径、椭球体或球体一致。
- 是否影响地表颜色，还是单独后处理。
- 移动端是否有降级方案。

大气散射是渲染模型，不等于真实气象模型。

## 光照

光照系统应区分：

- 环境光 ambient。
- 太阳直射 directional light。
- 夜间城市灯光或自发光 emissive。
- 模型 PBR 光照。
- 地形和 3D Tiles 光照。

必须明确：

- 光源方向坐标系。
- 色温、强度、曝光和 tone mapping。
- 地形、模型、矢量覆盖物是否参与光照。
- 夜间模式是否改变数据样式。
- 业务颜色是否允许被光照影响。

警告、风险区、分析结果等业务颜色通常不应被光照改变到无法识别。

## 阴影

阴影可能来自：

- 地形阴影。
- 3D Tiles 建筑阴影。
- 模型阴影。
- 日照分析结果。

必须明确：

- 阴影只是视觉效果，还是分析结果。
- shadow map 分辨率、范围和级联策略。
- 是否支持软阴影。
- 是否影响透明对象。
- 性能预算。

日照分析不能只依赖视觉阴影截图，必须有时间、位置、太阳角度和遮挡模型的可复现计算。

## 云

云可以是：

- 静态云层纹理。
- 程序化噪声云。
- 气象云量/卫星云图瓦片。
- 体积云。

必须明确：

- 云层高度。
- 是否投影到地球表面。
- 是否随时间移动。
- 数据时间和更新频率。
- 与大气、光照和阴影的关系。
- 是否遮挡 picking 或只是背景效果。

## 雾、雨、雪和能见度

天气效果必须区分视觉与数据：

- 雾：屏幕空间雾、距离雾、真实能见度数据。
- 雨雪：粒子效果、雷达/预报数据、地面观测。
- 雷暴：视觉闪电、真实告警。

必须明确：

- effect volume：全球、区域、相机附近，还是数据网格。
- 粒子数量和性能预算。
- 是否影响地表颜色、交通态势或业务告警。
- 真实气象数据的时间、单位和有效范围。

## 风场与流场

风场、洋流、河流流向常用粒子或纹理平流表达。

必须明确：

- 数据格式：GRIB、NetCDF、GeoTIFF、矢量网格、瓦片。
- u/v 分量单位。
- 高度层或压力层。
- 时间步长。
- 插值方式。
- 粒子密度和速度缩放。

不要把视觉粒子速度当作真实风速，除非明确标定。

## 海洋和水体

水体可能包括：

- 静态水面材质。
- 动态波浪。
- 潮汐、水位、淹没范围。
- 海温、海流、浪高。

必须明确：

- 水面高度基准。
- 波浪是视觉还是数据驱动。
- 水体是否参与地形遮挡和 picking。
- 洪水/淹没分析是否有真实高程和水位模型。

## 环境 Provider

环境数据也应通过 Provider 接入：

- `SkyProvider`
- `AtmosphereProvider`
- `LightingProvider`
- `WeatherProvider`
- `CloudProvider`
- `OceanProvider`
- `TimeProvider`

每个 Provider 必须说明数据来源、时间、单位、范围、更新频率、缓存和降级策略。

## 渲染顺序

推荐大致顺序：

1. sky / stars
2. atmosphere back layer
3. globe / terrain / imagery
4. 3D Tiles / models
5. vector overlays
6. clouds / weather volumes
7. atmosphere front layer / fog / postprocess
8. labels / UI overlays

实际顺序需结合 depth、透明排序和后处理设计。

## 验收清单

实现环境效果后至少验证：

- 白天、夜晚、日出日落场景。
- 高空、近地、太空视角。
- 太阳方向和阴影方向一致。
- 大气没有遮挡 UI 或业务图层。
- 天气效果可关闭。
- 视觉效果不会改变分析数据值。
- 移动端或低性能设备有降级策略。
- 时间拖动时环境状态同步变化。
